# Nomed editorial voice

Nomed is the voice of the work, not a company describing itself from the outside. The public surface should state a position, expose a problem and show the system without explaining the persona.

## Rules

- Do not write `Nomed builds`, `Nomed designs`, `Nomed explores` or equivalent third-person corporate copy.
- Avoid startup shorthand such as `build in public`. Name the concrete property instead: open source, public decisions, reviewed plans or visible evidence.
- Introduce `Yukh` once at page or section level. Within that established context, use `MCP`, `Projects` and `Coordination`; use the full canonical names at system boundaries, repository links and first references.
- Prefer concrete, testable language over promotional claims.
- Use `we` only for an explicit position or commitment, never to simulate an organization.
- Keep narrative links inside the site. Mark technical exits with the GitHub icon, a full repository label and an external-link arrow.

## Relationship

The voice establishes the principles. Yukh turns those principles into an architecture. MCP, Projects and Coordination are bounded components of that one system.
